Pantheon Panel

My own server panel for building and running Minecraft server networks

Pantheon Panel is a self-built server management panel, inspired by Pterodactyl but made for the way I actually work: spinning Minecraft servers up and dropping them whenever I want. Projects, blueprints, a key vault and custom dashboards keep everything in one web app that both I and an AI can manage.

I got the inspiration from Pterodactyl, a panel made for server hosts who sell servers to other people, who then get their own instance nodes. We used a whole dedicated server ourselves with Pterodactyl, and I kept getting annoyed with how it felt and how we used it compared to what it was made for.

We wanted to spin up Minecraft servers and drop them whenever — and in Pterodactyl that doesn't look very pretty. I could have listed a massive amount of pain points.

I could also have just used Docker and a terminal. But would I really be in IT if I just used the terminal of the dedicated server? So I made it the way I felt would be super useful to me — and for AI to add the things I need.

Goal

A panel for people who actually want to build a Minecraft server network: spin servers up and drop them whenever, keep everything in one place, and let an AI help manage it.

Features

  • Projects: I have a lot of ideas and projects that sometimes need to talk to each other and sometimes don't — each project is its own network
  • Private by default: Pterodactyl pushes every container to a public IP unless told otherwise. Pantheon is the other way around — only what has to be public is public, and even then it isn't forwarded in the firewall
  • Key Vault: secrets aren't all sitting in one place where one web hack gets everything
  • Blueprints: reusable containers (an AI can make one) so I can stay in the web app and see broader statistics
  • Custom UI elements per blueprint — e.g. my scaler service that scales Minecraft servers shows what it's doing, and why, on the server page
  • Dashboards, nodes, backups, users & access and API keys
  • MCP / API keys so Claude can set things up — managing a whole server cluster in 5 minutes

How it's built

Mythos daemons run on the nodes and start the containers. Servers are deployed from blueprints into projects, each with its own network, and a Velocity gateway exposes only what has to be public. Blueprints can ship their own UI that reads a service out, like the scaler.

Roadmap

  • Publish it in the future (I won't recommend anyone to use it yet — I don't fully trust it)
  • Ready-made blueprints, like custom Minestom lobbies
  • Easily link a few VPSs into one panel

Dev log

Why I built my own panel

2026-11-19 · milestone

Pterodactyl never felt right for how we used it, so I built Pantheon around projects, private-by-default networking, a key vault and blueprints.

The goal: creating a server network has never been easier. Buy a few VPSs, link them into one panel with a few commands, use the scaler service, and run what you want to run — I even have some custom Minestom lobby blueprints. Now anyone in the world can play on your server.

And if you're too lazy to do the settings: create an API key, give it to Claude, and he'll do it for you in 5 minutes.

Private by default, vault for secrets

2026-11-19 · update

Pterodactyl pushes every container to a public IP unless you say otherwise. I switched it around: only when something has to be public is it public, and then it's not even forwarded in the firewall, because I'm not crazy.

I also added a key vault, because in Pterodactyl all the passwords just live in one place — one web hack and everything is gone. A little extra layer to make it safer.
