Minecraft EpicKingdom Manager

A modular core plugin that turns one Minecraft gamemode into swappable extensions

EpicKingdom is the core of a custom Minecraft kingdom gamemode I build with CrownForge. Instead of 20 separate plugins cluttering the plugins folder, everything lives in one contained plugin that loads gameplay features as extensions. Because features change a lot with this kingdom idea, almost everything is built on interfaces so it can be replaced without breaking the rest.

The goal was to make the custom gamemode more contained in its own plugin, instead of trashing the plugins folder with 20 plugins that each do a different task.

The second goal was making it easy to switch features out, because those change often with this idea of a kingdom we are making. For example, we have had square regions and custom-shaped regions, and we have used different web tools for them. If something was already made once, we can save it and start something new and expect 90% to still work, because it was anticipated and built on interfaces so anything can be replaced easily.

This project shows my deep understanding of Java, down to the level of abstraction, encapsulation and so on. And I wrote it because I had an AI subscription, which is crazy.

The source code stays private, so on this page you'll find the architecture instead.

Goal

One contained plugin for the whole gamemode, where every feature is an extension that can be swapped, rewritten or dropped without touching the rest.

Features

  • Extension system: each extension is its own JAR, loaded in its own isolated class loader
  • Annotation-driven managers with automatic discovery, injection and lifecycle hooks
  • Interfaces everywhere, so implementations can be replaced without changing the code that uses them
  • Three ways for extensions to talk: core managers, a type-safe cross-extension API, and a loose map-based API
  • Permission sync that calculates what changed since the last session and updates LuckPerms automatically
  • Custom events for every important kingdom action
  • Kingdom chat with channels, plus cross-server support through Velocity
  • Integrations with WorldGuard, PlaceholderAPI, LuckPerms and TAB
  • Folia-ready scheduling

How it's built

A small core owns the extension runtime (loading, dependency resolution, injection, lifecycle) and exposes managers as interfaces. Gameplay features are extensions on top. Layers only talk downward through interfaces, which is what makes parts swappable.

Roadmap

  • Keep growing the extension library as the kingdom concept evolves
  • Publish more of the architecture documentation
