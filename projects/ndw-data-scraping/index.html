NDW Data Collector

A data collector that gathers Dutch & Belgian traffic, weather and event data to hunt for correlations

Not an actual scraper: it just sends requests to the open API of the Nationaal Dataportaal Wegverkeer (NDW). Alongside the Dutch traffic data I'm collecting some Belgian road services and a weather API, and eventually events, because those can have fun correlations. It's been running for about 20 days and I'm waiting for a ton of data so I can look for correlations over longer periods.

I've always wanted to do something like this but never really found the time. Now it's been running for about 20 days, and I'm just waiting for it to collect a ton of data so I can look for correlations over longer periods.

I obviously don't have 10 years of data. If someone does, let me know — I would love to take a crack at it!

Goal

No big plan — it's for fun. Collect the data first, then find out what correlations show up between traffic, weather, Belgian road services and eventually events.

Features

  • Requests to the NDW open API (the Dutch traffic data)
  • Some Belgian road services
  • A weather API
  • Events, eventually — they can have fun correlations
  • Compact storage: sorted per day, roughly 1 GB per day (500 MB compressed)
  • A live map explorer with layers for speeds, measures, road works, truck parkings and charging points
  • Runs as a collector and a cleaner on my Pantheon panel

How it's built

Collectors call the APIs on a schedule and a cleaner process shrinks the raw data into a compact format sorted per day, stored on a hard drive. A separate application reads the data out for the dashboards and map.

Roadmap

  • Wait for a lot more data, then search for longer-period correlations
  • Add events as a data source
  • Compress the data even further

Dev log

From 15 GB to 1 GB per day

2026-11-18 · problem

I thought just collecting everything on my Pi and eventually moving it to my computer would go totally fine. Nothing could go wrong... 18 days of data in, I already had hundreds of gigabytes.

It was my own fault. I hadn't really looked at the data yet: I had let Claude Code build a dashboard and quickly made an application to read all the data out and store it sorted per day. And I'm lucky I checked now and not 30 days later, because I wasn't going to look at it otherwise.

200 GB was already there, on a slow HDD. Downloading it took hours and I thought: it can't be that much, right? It turned out to be bad data. I made sure all the invalid fields were dropped, and since there's a static set of names for specific sensors, I saved those apart and linked them to an id, so the numbers got super small.

Result: from about 15 GB per day to about 1 GB per day, which makes it possible to let this run for years. Compression takes it to 500 MB.

How I shrank the data

2026-11-18 · solution

I'll probably be able to compress it even further if I take some more looks. For now I did the following:

• Data that gave back zero can go — I'll know by it not being there

• Values with a limited set of states (like "true|false" or some other name) are bound to a number

• Dates were sometimes in every item; I define the time once and nest items under it, or again use a number

• It becomes humanly unreadable, but that's what dashboards are for...

• All variables are renamed to the shortest possible version (time becomes t) and a static file defines all the short names with the full word and a description, so I still know what they mean in a few years
